改动内容：

  1. build.gradle — 添加 Kotlin JVM 插件 (2.2.21) 和 kotlinx-coroutines-core 依赖，设置 Kotlin 编译目标为 JVM 17
  2. 新建 ReadActionCompat.kt — Kotlin 协程封装，提供两个 Java 可调用的静态方法：

    - computeInReadAction(Runnable) — 无返回值的 read-action
    - computeInReadActionWithResult(() -> T) — 有返回值的 read-action
    - 内部使用 withContext(Dispatchers.Default) + ReadAction.computeCancellable() 替代弃用 API
  3. SuccessCompileStatusNotification.java — ReadAction.run() → ReadActionCompat.computeInReadAction()
  4. ExportPatcherDialog.java — ReadAction.computeBlocking() → ReadActionCompat.computeInReadActionWithResult()

  核心思路：Kotlin 侧用协程 suspend 函数 + ReadAction.computeCancellable() 执行读操作，再用 runBlocking 包装成 Java
  可直接调用的静态方法，避免 Java 侧使用即将弃用的 ReadAction.run() / ReadAction.computeBlocking()。

修复内容：

  1. ExportPatcherDialog.onOK() — 在使用 module 前增加 module.isDisposed() 检查，如果模块已释放则提示用户重新打开对话框
  2. CompileExecutor.run() — 在调用 CompilerManager.make() 前增加 module.isDisposed() 检查，避免对已释放的模块发起编译

  AlreadyDisposedException 的根因是模块在对话框打开期间被卸载（如项目结构变更），使用已 disposed 的 module
  触发了内部断言。加前置检查后，会友好地提示错误而不再抛异常。
